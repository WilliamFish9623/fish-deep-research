# 四 汇总与报告生成

## 前置检查

`results/` 下已有 JSON；`fields.yaml` 可读；对象数与提纲一致，缺项已列明。

## 摘要字段选择

先扫描所有 JSON，列出适合放进目录的短字段，例如发文时间、文号、覆盖人数、指标值。向用户确认目录中显示哪两到三个，不要默认全部显示。

## 汇总脚本规则

在 `{topic}/` 下生成 `generate_report.py`，读取全部 JSON 与 fields.yaml，输出 `report.md`。脚本需满足五条。

第一，兼容两种 JSON 结构：扁平结构，字段在顶层；嵌套结构，字段在分类子字典中。查找顺序为顶层、分类映射键、遍历嵌套字典。

第二，建立分类双向映射。fields.yaml 的分类名与 JSON 的键可能是中中、中英、英中、英英四种组合，脚本要能互认。当前内置映射如下，可按实际字段表增删。

```python
CATEGORY_MAPPING = {
    "基本信息": ["basic_info", "基本信息"],
    "制度与依据": ["institution_basis", "policy_basis", "制度与依据"],
    "做法与机制": ["practice_mechanism", "mechanism", "做法与机制"],
    "成效与证据": ["outcomes_evidence", "outcomes", "成效与证据"],
    "争议与局限": ["debates_limitations", "limitations", "争议与局限"],
}
```

第三，复杂值格式化。字典列表每个字典一行，用竖线分隔键值；普通列表短则逗号连接，长则换行；嵌套字典递归展开；超过一百字的文本独立成段。

第四，收集额外字段。JSON 中有而 fields.yaml 未定义的字段放入「其他信息」，但要过滤内部字段 `_source_file` 与 `uncertain`，以及作为容器的分类键。

第五，跳过不确定值。字段值含 `[不确定]`、字段名在 uncertain 数组中、值为空，三种情况均跳过，并在报告末尾单列「未获取项」。

## 目录格式

目录必须包含每一个对象，每项显示序号、名称（锚点链接）与用户选定的摘要字段。示例：`1. [案例一](#案例一) - 发文时间: 2023-06 | 覆盖人数: 3000`。

## 降级路径

不能生成或执行脚本时，按同一套规则手工汇总，产物结构一致，并在报告末尾注明「本次为手工汇总」。

## 报告结构建议

摘要、研究问题与方法、来源分层说明、分对象正文（按字段分类）、跨对象比较、局限与未获取项、结论与建议、参考资料。

跨对象比较是报告的核心增值部分。逐对象罗列只是台账，比较才能产出判断：哪些做法收敛，哪些分歧，分歧背后的条件是什么。

## 交付前检查

对照根目录 `SKILL.md` 的五道门禁逐条检查。此外确认三件事：每个对象都有锚点且可跳转；参考资料按引用顺序编号；正文没有占位符与「待补充」。

## 反模式

直接把 JSON 拼成报告，不做比较。目录只列部分对象。不确定值被静默丢弃，读者不知道缺了什么。分类映射对不上，全部字段掉进「其他信息」。报告过长但没有结论。
